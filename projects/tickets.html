The board

Six lanes, one SQLite file

A lane board — todo, plan, develop, test, verify, done — that sits beside Jira for the local loop. I write cards and drag them in the browser, Claude Code works the same cards over MCP, and both share one SQLite file. Each project has its own tab, and the board reloads itself the moment anyone else writes.

The skills

Start, stop, open

Running /tickets-start in a Claude Code session opened in a project sets the repo up where needed — the MCP server, the test and deploy rules in its CLAUDE.md, the project on the board — and then works the board every 15 minutes for as long as the session stays open. /tickets-stop ends the loop, and /tickets-open-board brings the board up in the browser.

The agents

Plan, ask, build, test, land

Each run takes every ready card through to verify, up to three at once, and every stage starts a fresh subagent with the whole card pasted in. It plans first and leaves open questions on the card as clickable options; I answer, and the next run replans with them. Then it builds on a card/<id> branch in its own worktree, ticking the card's checklist as it goes, reviews with /code-review plus the project's tests, merges or opens a pull request, and deploys. Verify is mine.

The log

Who did what

Every write appends an event with its actor, so each card carries who did what and links to the Claude Code session that worked it, ready to resume. One local process and two dependencies — and this page is built on it, card by card.
